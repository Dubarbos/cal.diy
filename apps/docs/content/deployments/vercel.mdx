# Vercel

## Requirements

Currently Vercel Pro Plan is required to be able to Deploy this application with Vercel, due to limitations on the number of serverless functions and Cron Jobs on the free plan.

You need a Postgres database hosted somewhere. [Supabase](https://supabase.com) offers a great free option.

## Deployment

### 1. Create a Supabase project

1. Create a new project at [supabase.com](https://supabase.com).
2. Go to **Project Settings > Database > Connection string** and copy two connection strings:
   - **Transaction pooler** (port `6543`) → this becomes `DATABASE_URL`.
   - **Direct connection** (port `5432`) → this becomes `DATABASE_DIRECT_URL` (used only for running migrations, which don't work through the pooler).

### 2. Fork and clone the repository

```bash
git clone https://github.com/<<your-fork>>/cal.diy.git
```

### 3. Set environment variables

Copy `.env.example` at the repo root to `.env` and fill it in. At minimum you need:

- `DATABASE_URL` / `DATABASE_DIRECT_URL` — from step 1.
- `NEXT_PUBLIC_WEBAPP_URL` / `NEXTAUTH_URL` — your Vercel deployment URL (e.g. `https://your-app.vercel.app`), both should match.
- `NEXTAUTH_SECRET` — generate with `openssl rand -base64 32`.
- `CALENDSO_ENCRYPTION_KEY` — generate with `openssl rand -base64 24`.
- `CRON_API_KEY` — generate with `openssl rand -hex 16`.
- `CRON_SECRET` — generate with `openssl rand -hex 16`. Set this **as a Vercel Environment Variable** too — Vercel automatically sends it as a bearer token when it triggers the scheduled routes defined in `apps/web/vercel.json`, which is what actually authenticates Vercel's Cron Jobs.

See [manual setup](/installation) for the rest of the optional integrations (email, calendars, video, etc).

### 4. Install packages and set up the database

```bash
yarn install
yarn workspace @calcom/prisma db-deploy
```

`db-deploy` runs Prisma migrations against `DATABASE_DIRECT_URL`.

### 5. Create your first user

```bash
yarn db-studio
```

Open the `User` model, add a new record (encrypt the password with [BCrypt](https://bcrypt-generator.com/) first), and save it.

### 6. Deploy to Vercel

1. Create a new project on Vercel and import your forked repository.
2. Set **Root Directory** to `apps/web`.
3. Add the environment variables from step 3 (Production + Preview as needed).
4. Deploy.

Build command, install command, function timeouts, and the Cron Jobs schedule are already committed in [`apps/web/vercel.json`](https://github.com/calcom/cal.diy/blob/main/apps/web/vercel.json), so you shouldn't need to override anything manually in the dashboard. It wires up the following scheduled routes (all under `/api/cron/*`): booking reminders, webhook triggers, travel-schedule timezone changes, calendar cache subscriptions/cleanup, selected-calendars sync, and app metadata sync.

> If `yarn install` fails during the Vercel build with an immutable-lockfile error, add `YARN_ENABLE_IMMUTABLE_INSTALLS=false` as an environment variable.
